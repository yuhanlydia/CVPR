# r003 code-debug round

This file records implementation findings before the next native GPU run. It
does not reinterpret the earlier developmental scores and does not advance a
scientific gate.

## Repairs

- **I03** now has an explicit `distance` score path. Its PSD matrix scores
  `-(q-c)^T M (q-c)`; it no longer falls through to the bilinear dot-product
  scorer. Runtime checks reject non-symmetric or non-PSD metrics.
- **I10, I13, and C_WHITEN** now L2-normalize transformed two-view features
  before dot-product ranking. The output dimension and query/candidate norm
  ranges are recorded for every task, so CCA truncation and norm drift are
  observable rather than hidden in the ranker.
- **All non-RBF heads** now reject mismatched dimensions, non-finite values,
  and zero transformed features before native ranking. I12 and I16 retain
  their declared diffusion/Nystrom feature definitions; their dimensions and
  norm ranges are logged for diagnosis instead of silently changing the
  method.

## I09 verification

- The implementation matches the declared one-step, ridge-damped logistic
  quadratic system. A dense-Hessian unit test independently reproduces the
  sample-space solve to numerical precision; teacher and student margins use
  the same temperature, with fixed training-only pairs.
- The latest native developmental receipt reports soft-target CE decreasing
  from 0.5341 to 0.4788. Its maximum margin step is 5.058, so the local
  curvature approximation is large-step and must not be described as a global
  Newton guarantee. The observed training-loss decrease does not establish
  generalization.
- The current C_KD control fits squared margins, not the same soft-target CE.
  Therefore the I09 score is not a matched test of the curvature contribution;
  an equal-data/equal-budget optimized CE control remains required.
